# Project Documentation: Komorebi Kiln (Japanese Porcelain E-Commerce)

An artisanal e-commerce storefront for handcrafted Japanese ceramics and porcelain (Arita-yaki, Hasami, Mino-ware, Kutani, and Bizen). Built with a minimalist Japanese aesthetic (warm stone tones, serif typography, negative space) and an integrated Stripe payment pipeline.

* **Local Storage & Database:** File-system JSON DB (data/products.json) + Node fs/promises
* **Media Management:** Local file uploads (public/uploads/products/) via Next.js Route Handlers

## 3. What Has Been Built & Configured

### A. Core Architecture & Styling
* Scaffolded Next.js App Router with TypeScript and Tailwind CSS.
* Separated Data Types (types/product.ts): Prevented client browser bundles from importing server-only Node modules (fs).
* Resolved Hydration Warnings: Added suppressHydrationWarning to <html> and <body> in app/layout.tsx to handle browser extensions (e.g., Grammarly).

### B. Product Catalog & Presentation
* Homepage (app/page.tsx):
  - Editorial hero section with collection overview.
  - Tradition/Style filter tabs (Arita-yaki, Hasami-yaki, Mino-yaki, Bizen-yaki, Kutani-yaki).
  - Asynchronous fetching from /api/products with loading state.
* Product Card (components/ProductCard.tsx):
  - Subtle hover zoom and "One of a Kind" badge support.
  - Direct + quick-add button wired into Zustand.
* Dynamic PDP (app/products/[slug]/page.tsx & ProductDetailClient.tsx):
  - Pre-rendered static paths via generateStaticParams.
  - Dynamic SEO metadata generation.
  - Multi-angle image thumbnail switcher.
  - Physical specifications breakdown (Height, Diameter, Weight, Fluid Capacity) and traditional care instructions.
  - Dual actions: "Add to Selection" and immediate "Direct Checkout".

### C. Shopping Cart (Zustand)
* Store (stores/useCartStore.ts):
  - Manages item IDs, names, prices (in integer cents), thumbnails, and quantities.
  - Persists items across sessions via localStorage under key porcelain-cart-storage.
  - Auto-calculates subtotal and item count.
* Slide-Over Drawer (components/CartDrawer.tsx):
  - Off-canvas slide-out panel with smooth transition curves.
  - Background scroll locking when open.
  - In-cart quantity adjustment and item removal.

### D. Stripe Checkout & Payment Flow
* Checkout API (app/api/checkout/route.ts):
  - Validates item IDs on the server against the local database (getProducts()).
  - Restricts checkout to card payments and supported international shipping countries (US, CA, GB, FR, DE, JP, AU).
  - Resolves images dynamically: uses external URLs or applies a fallback public ceramic placeholder during localhost testing (preventing Stripe 400 errors).
* Order Confirmation (app/success/page.tsx):
  - Reads session_id query parameter and verifies it on the server using Stripe's SDK.
  - Renders an itemized collector receipt and total settled amount.
  - Triggers ClearCartOnSuccess to empty the cart once paid.
* Webhook Fulfillment (app/api/webhook/route.ts):
  - Verifies stripe-signature using STRIPE_WEBHOOK_SECRET.
  - Handles checkout.session.completed to log or dispatch orders.

### E. Studio Asset & Product Management (Admin)
* Upload Route (app/api/upload/route.ts):
  - Receives multipart FormData via POST.
  - Validates MIME types (JPEG, PNG, WEBP, AVIF).
  - Generates timestamped, sanitized filenames and writes them to public/uploads/products/.
* Database API (app/api/products/route.ts):
  - Automatically generates URL slugs from English titles.
  - Converts standard decimal prices (e.g., $68.00) to integer cents (6800) for Stripe.
  - Persists new works into data/products.json.
* Admin Dashboard (app/admin/page.tsx):
  - Drag-and-drop local image uploader (components/ImageUploader.tsx).
  - Form for title, Japanese Kanji, style, region, price, dimensions, and care notes.
  - Live inventory sidebar displaying all active catalog pieces with direct storefront links.

## 3. Engineering Changelog & Problem Resolutions

### A. TypeScript Decoupling & Server-Module Leaks
* **Problem:** Importing data functions directly into client components pulled Node.js fs/promises into client bundles, triggering Module not found: Can't resolve 'fs'.
* **Fix:** Split data types into a pure types/product.ts file so client components (e.g., page.tsx, ProductCard.tsx) never import server-side runtime files.

### B. Hydration Warning Suppression
* **Problem:** Extensions such as Grammarly injected data attributes into <body> before hydration, causing React SSR hydration mismatch warnings.
* **Fix:** Added suppressHydrationWarning to both <html> and <body> in app/layout.tsx.

### C. Public Checkout Previews & Image Handling
* **Problem:** Stripe Hosted Checkout cannot render images hosted on localhost/private network paths, failing line item image previews.
* **Fix:** Configured app/api/checkout/route.ts to provide a reliable public ceramics placeholder when on localhost, and to pass full public CDN URLs in production.

### D. Production Deployment & Custom Domain
* **Domain:** www.appos.co.uk (registered via GoDaddy).
* **DNS Configuration:**
  - CNAME (www) -> cname.vercel-dns.com
  - A Record (@) -> 76.76.21.21
* **Webhook Routing:** Pointed live Stripe event listeners to https://www.appos.co.uk/api/webhook.

### E. Admin Security via Edge Middleware
* **Implementation:** Created root middleware.ts checking Authorization headers against ADMIN_USER and ADMIN_PASSWORD.
* **Robust Decoding:** Handled base64 parsing via Buffer to prevent truncation issues with passwords containing colons or symbols.

### F. Cloud Persistence Migration (Upstash Redis)
* **Problem:** Vercel serverless environments enforce a read-only filesystem (/var/task), throwing EROFS crashes when trying to write to products.json.
* **Migration:** Deprecated @vercel/kv in favor of official @upstash/redis.
* **Resilience:** Implemented data/products.ts with automatic failover to data/products.json if credentials are unavailable, and built-in auto-seeding when Redis is unpopulated.

### G. Edge Asset Storage (Vercel Blob)
* **Implementation:** Integrated @vercel/blob in app/api/upload/route.ts with a local fallback for offline development.
* **Configuration:** Whitelisted *.public.blob.vercel-storage.com under images.remotePatterns in next.config.ts.

### H. 404 Route & Cache Invalidation Resolution
* **Problem:** Newly created items in Redis threw 404 "Page Not Found" because Next.js pre-rendered dynamic paths only at build time.
* **Fix:**
  - Added export const dynamicParams = true and export const dynamic = 'force-dynamic' to app/products/[slug]/page.tsx.
  - Added on-demand revalidatePath calls in app/api/products/route.ts for /, /admin, and /products/[slug].
