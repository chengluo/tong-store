## 3. What Has Been Built & Configured

### A. Core Architecture & Styling
* Scaffolded Next.js App Router with TypeScript and Tailwind CSS.
* Separated Data Types (types/product.ts): Prevented client browser bundles from importing server-only Node modules (fs).
* Resolved Hydration Warnings: Added suppressHydrationWarning to <html> and <body> in app/layout.tsx to handle browser extensions (e.g., Grammarly).

### B. Product Catalog & Presentation
* Homepage (app/page.tsx):
  - Editorial hero section with collection overview.
  - Tradition/Style filter tabs (Arita-yaki, Hasami-yaki, Mino-yaki, Bizen-yaki, Kutani-yaki).
  - Asynchronous fetching from /api/products with loading state.
* Product Card (components/ProductCard.tsx):
  - Subtle hover zoom and "One of a Kind" badge support.
  - Direct + quick-add button wired into Zustand.
* Dynamic PDP (app/products/[slug]/page.tsx & ProductDetailClient.tsx):
  - Pre-rendered static paths via generateStaticParams.
  - Dynamic SEO metadata generation.
  - Multi-angle image thumbnail switcher.
  - Physical specifications breakdown (Height, Diameter, Weight, Fluid Capacity) and traditional care instructions.
  - Dual actions: "Add to Selection" and immediate "Direct Checkout".

### C. Shopping Cart (Zustand)
* Store (stores/useCartStore.ts):
  - Manages item IDs, names, prices (in integer cents), thumbnails, and quantities.
  - Persists items across sessions via localStorage under key porcelain-cart-storage.
  - Auto-calculates subtotal and item count.
* Slide-Over Drawer (components/CartDrawer.tsx):
  - Off-canvas slide-out panel with smooth transition curves.
  - Background scroll locking when open.
  - In-cart quantity adjustment and item removal.

### D. Stripe Checkout & Payment Flow
* Checkout API (app/api/checkout/route.ts):
  - Validates item IDs on the server against the local database (getProducts()).
  - Restricts checkout to card payments and supported international shipping countries (US, CA, GB, FR, DE, JP, AU).
  - Resolves images dynamically: uses external URLs or applies a fallback public ceramic placeholder during localhost testing (preventing Stripe 400 errors).
* Order Confirmation (app/success/page.tsx):
  - Reads session_id query parameter and verifies it on the server using Stripe's SDK.
  - Renders an itemized collector receipt and total settled amount.
  - Triggers ClearCartOnSuccess to empty the cart once paid.
* Webhook Fulfillment (app/api/webhook/route.ts):
  - Verifies stripe-signature using STRIPE_WEBHOOK_SECRET.
  - Handles checkout.session.completed to log or dispatch orders.

### E. Studio Asset & Product Management (Admin)
* Upload Route (app/api/upload/route.ts):
  - Receives multipart FormData via POST.
  - Validates MIME types (JPEG, PNG, WEBP, AVIF).
  - Generates timestamped, sanitized filenames and writes them to public/uploads/products/.
* Database API (app/api/products/route.ts):
  - Automatically generates URL slugs from English titles.
  - Converts standard decimal prices (e.g., $68.00) to integer cents (6800) for Stripe.
  - Persists new works into data/products.json.
* Admin Dashboard (app/admin/page.tsx):
  - Drag-and-drop local image uploader (components/ImageUploader.tsx).
  - Form for title, Japanese Kanji, style, region, price, dimensions, and care notes.
  - Live inventory sidebar displaying all active catalog pieces with direct storefront links.

## 3. Engineering Changelog & Problem Resolutions

### A. TypeScript Decoupling & Server-Module Leaks
* **Problem:** Importing data functions directly into client components pulled Node.js fs/promises into client bundles, triggering Module not found: Can't resolve 'fs'.
* **Fix:** Split data types into a pure types/product.ts file so client components (e.g., page.tsx, ProductCard.tsx) never import server-side runtime files.

### B. Hydration Warning Suppression
* **Problem:** Extensions such as Grammarly injected data attributes into <body> before hydration, causing React SSR hydration mismatch warnings.
* **Fix:** Added suppressHydrationWarning to both <html> and <body> in app/layout.tsx.

### C. Public Checkout Previews & Image Handling
* **Problem:** Stripe Hosted Checkout cannot render images hosted on localhost/private network paths, failing line item image previews.
* **Fix:** Configured app/api/checkout/route.ts to provide a reliable public ceramics placeholder when on localhost, and to pass full public CDN URLs in production.

### D. Production Deployment & Custom Domain
* **Domain:** www.appos.co.uk (registered via GoDaddy).
* **DNS Configuration:**
  - CNAME (www) -> cname.vercel-dns.com
  - A Record (@) -> 76.76.21.21
* **Webhook Routing:** Pointed live Stripe event listeners to https://www.appos.co.uk/api/webhook.

### E. Admin Security via Edge Middleware
* **Implementation:** Created root middleware.ts checking Authorization headers against ADMIN_USER and ADMIN_PASSWORD.
* **Robust Decoding:** Handled base64 parsing via Buffer to prevent truncation issues with passwords containing colons or symbols.

### F. Cloud Persistence Migration (Upstash Redis)
* **Problem:** Vercel serverless environments enforce a read-only filesystem (/var/task), throwing EROFS crashes when trying to write to products.json.
* **Migration:** Deprecated @vercel/kv in favor of official @upstash/redis.
* **Resilience:** Implemented data/products.ts with automatic failover to data/products.json if credentials are unavailable, and built-in auto-seeding when Redis is unpopulated.

### G. Edge Asset Storage (Vercel Blob)
* **Implementation:** Integrated @vercel/blob in app/api/upload/route.ts with a local fallback for offline development.
* **Configuration:** Whitelisted *.public.blob.vercel-storage.com under images.remotePatterns in next.config.ts.

### H. 404 Route & Cache Invalidation Resolution
* **Problem:** Newly created items in Redis threw 404 "Page Not Found" because Next.js pre-rendered dynamic paths only at build time.
* **Fix:**
  - Added export const dynamicParams = true and export const dynamic = 'force-dynamic' to app/products/[slug]/page.tsx.
  - Added on-demand revalidatePath calls in app/api/products/route.ts for /, /admin, and /products/[slug].

## Session Update — 2026-09-20: Inventory Management & Admin CMS Rebuild

### A. Cart Type Mismatch Fix
* **Problem:** `ProductCard.tsx` and `ProductDetailClient.tsx` called `addItem` with an explicit `quantity: 1` field, but `useCartStore`'s `addItem` is typed as `Omit<CartItem, 'quantity'>` since the store sets `quantity` itself (increments existing items, defaults new items to `1`). TypeScript flagged this as an excess-property error (`ts(2353)`).
* **Fix:** Removed the redundant `quantity: 1` from both call sites.

### B. Inventory Decrement on Checkout Webhook
* **Problem:** `app/api/webhook/route.ts` logged completed Stripe orders for fulfillment but never decremented product stock — inventory counts never changed after a successful purchase.
* **Fix:** Expanded the webhook's line-item retrieval to include `line_items.data.price.product`, read the `productId` metadata that `app/api/checkout/route.ts` already attaches to each Stripe product, and decrement matching product stock (clamped at 0) via the existing `saveProduct` helper. Revalidates `/`, the product's detail page, and `/admin` afterward.
* **Verified:** End-to-end test using the Stripe CLI (`stripe listen --forward-to`) plus a real test-mode Checkout Session completed with test card `4242 4242 4242 4242` — confirmed stock dropped from `1` to `0` after payment, then restored the test product's stock afterward.

### C. Admin CMS: Full-Field Edit Support
* **Problem:** The admin "Update Ceramic Piece" button silently failed to save most edits. `app/api/products/route.ts`'s `PATCH` handler only ever read `{ id, stock }` from the request body, ignoring name, price, dimensions, care instructions, and every other field the edit form submitted.
* **Fix:** `PATCH` now applies any field present in the body — converts `price` from dollars to cents (matching the create flow), splits a newline-delimited `careInstructions` string into an array, and merges dimension fields into the `dimensions` object — while still supporting the stock-only `{ id, stock }` calls used by the inline +/- steppers.
* **Verified:** Simulated the edit form's exact payload shape via `curl`; confirmed description, price, dimensions, and care instructions all persisted correctly, then restored the test product to its original values.

### D. Admin CMS: Restored Missing Form Fields
The admin product form (`app/admin/page.tsx`) went through several redesign iterations this session (`AdminPage` → `AdminTableDashboard` → `AdminSplitDashboard`). Several fields already existed in component state and were already sent to the API, but had no corresponding input in the JSX — they were silently stuck at their default values. Added:
* **Dimensions:** Height / Diameter / Weight / Capacity input grid
* **Care Instructions:** textarea (one instruction per line)
* **Origin Kiln / Prefecture:** text input
* **One-of-a-Kind checkbox:** "Unique collector item (One-of-a-Kind)", matching the styling introduced in the earlier `f31b187` commit

### E. Admin CMS: Sold-Out Styling
* Added a "Sold Out" pill to inventory rows when `stock <= 0`, matching the red pill styling defined in `public/mockup.html` (`.pill-soldout`: `#FEF2F2` background / `#B91C1C` text / `#FECACA` border → Tailwind `bg-red-50 text-red-700 border-red-200`).
* `public/mockup.html` was added to the repo as a static design reference for the admin CMS rebuild.

### F. Product Detail Page Enhancements
* Added a **Care Instructions** section to `components/ProductDetailClient.tsx`, rendering each item from `product.careInstructions` as a bulleted list, sized (`text-xs`) to match the adjacent Specifications block.
* Added a **Capacity** row to the Specifications grid, shown only when `product.dimensions.capacity` is present.

### G. Transactional Order Confirmation Email
* **Problem:** Buyers only ever saw the receipt at `app/success/page.tsx`. Closing that tab meant no persistent order reference or care-instructions reminder.
* **Fix:** Added `lib/email.ts` using the `resend` npm package. `sendOrderConfirmationEmail()` builds an itemized HTML receipt (name, quantity, unit price, subtotal, total) with each purchased product's care instructions rendered as a bulleted sub-list. `app/api/webhook/route.ts` calls it after stock decrement, using the customer email Stripe returns on `checkout.session.completed`.
* **Graceful degradation:** If `RESEND_API_KEY` is unset, the function logs a warning and returns without throwing — matching this codebase's existing fallback pattern for Redis/Blob.
* **Provider note:** Neither Resend nor Postmark exist in the Stripe Projects service catalog (checked via `stripe projects search`); the closest catalog matches (AgentMail, Customer.io, PostHog, PostalForm) aren't fit for transactional receipts, so Resend was integrated directly as an npm dependency instead.
* **Verified:** Two end-to-end test-mode checkouts via Stripe CLI + browser (test card `4242 4242 4242 4242`) — first confirmed the graceful skip path with no API key configured, second confirmed no errors were thrown once a real `RESEND_API_KEY`/`RESEND_FROM_EMAIL` were added to `.env.local`. The key is send-only restricted, so delivery couldn't be verified via the API directly, but `resend.emails.send()` completed without error. (See Section H for the deliverability follow-up.)

### H. Order Confirmation Email — Deliverability & Reference Format
* **Problem:** After adding a real `RESEND_API_KEY`, emails were accepted by Resend (`error: null`, valid message ID) but never arrived — not even in Gmail spam.
* **Root cause:** `appos.co.uk`'s SPF record (`v=spf1 include:spf.protection.outlook.com -all`) only authorized Microsoft 365 to send as the domain and hard-failed everyone else, including Resend's mail servers. DKIM was already correctly configured for Resend, but the conflicting SPF hard-fail caused Gmail to silently discard the message post-handoff rather than route it to spam.
* **Fix:** Added `include:send.forge.rmta.net` (Resend's SPF include, from the Resend dashboard's domain verification screen) to the existing SPF TXT record on GoDaddy, combining it with the existing Outlook include rather than replacing it:
  `v=spf1 include:spf.protection.outlook.com include:send.forge.rmta.net -all`
* **Verified:** A retest email after DNS propagation was confirmed delivered in the Resend dashboard and arrived in the recipient's Gmail inbox.
* **Remaining gap:** `_dmarc.appos.co.uk` still has no DMARC record. Not currently blocking delivery, but recommended for long-term sender reputation (a permissive `v=DMARC1; p=none;` policy is a safe starting point).
* **Separate finding — local webhook testing:** A real checkout completed through the actual `localhost:3000` site (not via the CLI/API test scripts) produced no email and no stock decrement. Cause: `stripe listen --forward-to localhost:3000/api/webhook` wasn't running. Stripe cannot deliver webhook events to a local machine without that CLI tunnel active — this is expected local-dev behavior, not a bug, and doesn't affect production (Stripe delivers directly to `https://www.appos.co.uk/api/webhook`).
* **Order reference format:** The email subject/heading originally showed the raw Stripe Checkout Session ID (e.g. `cs_test_a1C8Ojs...`), which reads as an internal ID rather than a customer-facing order number. Added `formatOrderReference()` in `lib/email.ts`, which strips the `cs_test_`/`cs_live_` prefix and formats the last 5 characters as `ORDER-XXXXX` (e.g. `ORDER-EVSQU`). The full Stripe session ID is still included lower in the email body as "Transaction ID" for support lookups.
